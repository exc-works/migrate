# 歷史與基線

遷移歷史表記錄版本、檔案名與哈希。判斷已經執行了哪些變更時，需要同時檢查歷史和實際資料庫結構。

## 查看狀態

```sh
migrate status
migrate status --output json
```

表格輸出 Version、Filename、Hash 和 Status；自動化流程可以讀取 JSON。

| 狀態 | 含義 | 後續操作 |
| --- | --- | --- |
| `pending` | 檔案尚未應用 | 檢查後運行 `up` |
| `applied` | 版本已成功應用 | 保持檔案不變 |
| `baseline` | 已登記歷史，但沒有執行檔案 | 保留接管時的歷史 |
| `outOfOrder` | 待執行版本低於已應用版本 | 檢查亂序策略 |
| `hashMismatch` | 當前檔案與記錄的哈希不同 | 恢復歷史檔案 |
| `filenameMismatch` | 當前檔案名與記錄不同 | 恢復歷史檔案名 |

哈希或檔案名不一致會阻斷執行。不要修改已應用遷移來完成新的結構變更，應新增更高版本。
指令碼校驗和只覆蓋入口源碼，不包含導入的 helper，見[模塊可復現性](./modules#checksums)。

## 為已有資料庫建立基線 {#baseline}

僅當資料庫已與要接管的遷移檔案一致時，才使用基線。它只登記歷史，不執行 SQL 或指令碼。

1. 對比現有結構、資料與遷移檔案。
2. 如有需要，先通過 `migrate create` 創建歷史表。
3. 執行 `migrate baseline`，再通過 `migrate status` 檢查。
4. 後續變更新增更高版本，按正常流程執行。

基線不能修復執行到一半的遷移。應先確定資料庫實際狀態；盲目登記歷史可能掩蓋尚未完成的變更。
