# 履歴とベースライン

履歴にはバージョン、ファイル名、ハッシュが記録されます。実際のスキーマと合わせて確認します。

```sh
migrate status
migrate status --output json
```

| 状態 | 意味 | 対応 |
| --- | --- | --- |
| `pending` | 未適用 | 確認して `up` |
| `applied` | 適用成功 | ファイルを変更しない |
| `baseline` | 実行せず登録 | 接管時の履歴を保持 |
| `outOfOrder` | 適用済みより低い未適用版 | 順序設定を確認 |
| `hashMismatch` | ファイル内容が履歴と異なる | 元の内容を復元 |
| `filenameMismatch` | ファイル名が履歴と異なる | 元の名前を復元 |

不一致は実行を停止します。変更は新しいバージョンに追加します。スクリプトのハッシュには[共有モジュール](./modules#checksums)は含まれません。

## 既存データベースのベースライン {#baseline}

既存スキーマとデータがファイルの内容と一致するときだけ使用します。

1. ファイルと実際の状態を比較します。
2. 必要なら `migrate create` で履歴テーブルを作成します。
3. `migrate baseline` を実行し、`migrate status` を確認します。
4. 今後の変更は高いバージョンで追加します。

SQL やスクリプトは実行されません。部分的に失敗した移行を修復するためのコマンドではありません。
