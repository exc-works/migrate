# マイグレーションの実行

設定が正しいデータベースとファイルを指していることを確認します。

## 履歴の初期化

```sh
migrate create
```

履歴テーブルがなければ作成します。マイグレーション本体は実行しません。既に変更が存在するデータベースには[ベースライン](./history#baseline)を確認してください。

## プレビューと実行

```sh
migrate up --dry-run
migrate up
migrate status
```

未適用バージョンを順に実行し、成功した履歴を記録します。再実行しても適用済みは繰り返しません。出力がない場合も `status` で確認できます。

Dry-run は履歴を読むために接続や SSH トンネルを使う場合がありますが、ユーザーの変更は実行しません。スクリプトと依存関係を検査するだけで、動的な SQL は表示できません。

## 古い未適用バージョン

既定では適用済みより低いバージョンはスキップします。現在のスキーマとの互換性を確認した上で、必要なら `migrate_out_of_order: true` にします。

## デプロイでの利用

```sh
migrate --non-interactive up
migrate --non-interactive status --output json
```

環境変数と SSH の認証情報を事前に渡し、同じデータベースへの実行は直列化します。履歴だけでは同時実行、クラッシュ、暗黙のコミットをまたぐ厳密な一度限りの実行を保証できません。失敗したら[データと履歴を確認](./troubleshooting)してから再試行します。
