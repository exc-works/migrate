# माइग्रेशन चलाएँ

लक्षित कनेक्शन और फ़ाइलें जाँचें।

```sh
migrate create
```

ज़रूरत पर केवल इतिहास तालिका बनती है, फ़ाइलें नहीं चलतीं। बदलाव पहले से हों तो [बेसलाइन](./history#baseline) देखें।

```sh
migrate up --dry-run
migrate up
migrate status
```

लंबित संस्करण क्रम से लागू और सफल इतिहास दर्ज होते हैं। लागू संस्करण दोहराए नहीं जाते। आउटपुट न भी हो तो status जाँचें। Dry-run इतिहास पढ़ने के लिए कनेक्शन/SSH खोल सकता है लेकिन बदलाव नहीं करता, स्क्रिप्ट नहीं चलाता और गतिशील SQL नहीं बता सकता।

लागू संस्करण से पुराने लंबित संस्करण डिफ़ॉल्ट रूप से छोड़े जाते हैं। वर्तमान स्कीमा से संगतता जाँचने के बाद `migrate_out_of_order` सक्रिय करें।

```sh
migrate --non-interactive up
migrate --non-interactive status --output json
```

वेरिएबल और सीक्रेट पहले दें, समान DB पर कमांड क्रम से चलाएँ। इतिहास समवर्ती रन, क्रैश या अप्रत्यक्ष commit के बीच ठीक एक बार चलना सुनिश्चित नहीं करता। दोहराने से पहले असली स्थिति देखें। [समस्या निवारण](./troubleshooting)।
