# Устранение неполадок

Начните с `migrate version`, `migrate capabilities --output json`, `migrate status --output json`. Только status требует соединение.

Проверьте PATH в [установке](./installation). Создайте настройки в проекте либо используйте `-c` / `-w`. В YAML проверяйте указанную позицию, значения и отступы пробелами, не Tab. См. [порядок поиска](./configuration#configuration-file-search-order).

`can't find env value for XXX` требует `${XXX}`. Значение `${XXX:default}` подходит лишь для несекретных полей. SSH `password_env` содержит имя переменной.

Для неподдерживаемого формата проверьте capabilities и обновитесь. Для `unsupported dialect` — [псевдонимы](./databases#aliases). Для модулей проверьте пути, установите npm, у встроенных источников задайте `DependencyDir`. Пакеты с Node или async несовместимы.

Восстановите применённые файлы и имена из Git, добавьте новую версию. Не обходите неизвестное состояние через baseline. Команда без вывода может быть успешной: проверьте applied, baseline, outOfOrder.

`to-version must be set, or use --all`: укажите цель или `--all`, цель сохраняется. Скрипт без down не откатывается.

Перед повтором проверьте данные и историю: DDL, нетранзакционные операции и разрыв около COMMIT могут оставить изменения. Baseline это не исправляет. Проверьте SSH-секреты, known_hosts, прокси и доступ бастиона к DB. Автопереподключения и повторов нет. Изучайте защищённые серверные журналы, не раскрывая секреты или данные.
