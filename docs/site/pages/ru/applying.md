# Применение миграций

Проверьте целевую базу и файлы.

```sh
migrate create
```

Создаёт только таблицу истории, если нужно. Если изменения уже существуют, сначала [baseline](./history#baseline).

```sh
migrate up --dry-run
migrate up
migrate status
```

Ожидающие версии выполняются по порядку, успех записывается. Повтор не переигрывает применённые. Вывода может не быть — проверьте status. Dry-run может читать историю и открывать SSH, но не выполняет изменения. Проверяет скрипты без вычисления динамического SQL.

Старые ожидающие версии по умолчанию пропускаются. `migrate_out_of_order` включайте после проверки совместимости со схемой.

```sh
migrate --non-interactive up
migrate --non-interactive status --output json
```

Переменные и секреты задавайте заранее, команды одной базы выполняйте последовательно. История не гарантирует однократность при конкуренции, сбое или неявном commit. Перед повтором проверьте состояние. См. [неполадки](./troubleshooting).
